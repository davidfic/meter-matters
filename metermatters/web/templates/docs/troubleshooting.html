When something doesn't file

The app would rather tell you what went wrong than guess. Here is each message it can give, what it means, and what to do.

A bill arrived by email but was not filed

Look at What has arrived on {{ app("web.connect", "Add bills") }}. Every message that reached your address is there with its reason.

The log saysWhat happenedWhat to do
Not from the utility's address, so not filed. It came from … The sender was not the utility's own notification address, and the message was not a hand-forward with the utility's address quoted inside. Check the filter matches the sender exactly as it appears on a real bill email. If you forwarded by hand, make sure your mail app included the original headers ("Forwarded message", From, Subject) rather than only the body.
Forwarded by …, who isn't you, so it wasn't filed A hand-forward is accepted only from the address you signed up with; this one came from somewhere else. Forward it from your sign-up address, or set a filter up in the mailbox the bills arrive in, which passes the utility's own message through.
The subject names neither electric nor gas The app tells the fuel from the subject line. Water bills by email are not read yet. Upload a water export or type the bill in. Electric and gas bills with an unusual subject: forward one by hand and, if it still says this, send the subject line to whoever runs the server.
Couldn't read a bill out of it The sender was right but the message's layout was not one the app knows. Today only Eversource's bill-ready email is read. Upload or type the bill in. Other utilities are being added; say which one you have.
The utility's signature on this message didn't verify The server is set to require a verified DKIM signature and this message's did not pass. Some forwarding paths rewrite the message on the way. Forward one by hand (hand-forwards are checked by the quoted sender instead). If the filter path always fails, tell the operator; the default setting files the bill and notes it instead of refusing.
Already on file The same bill had arrived before, or was in an upload. Nothing. It is counted once.
It matches none of your homes yet You have several homes and this account is new. Place it from the box at the top of the page. {{ doc("homes", "More than one home") }}

Nothing has arrived at all

  1. Forward one by hand to the address on the card. If that shows up in the log within a minute or two, the address works and the problem is the filter.
  2. Gmail: the address must be confirmed before any filter can use it. If the card shows a confirmation waiting, do it. If Gmail's Forwarding tab does not list the address at all, add it again. A filter only applies to mail that arrives after it was made. {{ doc("forwarding-gmail", "Gmail, step by step", "part-2") }} has every screen.
  3. Check the sender. Utilities use different addresses for bills, payments and marketing. Match the one on the "your bill is ready" email.
  4. Did you issue a new address? The old one stopped working at once; the filter has to be changed to the new one.
  5. If a hand-forward never shows up either, the server's inbound mail is down. Tell whoever runs it; the {{ doc("operators", "operators page") }} says where they should look.

An upload was turned away

The notice saysWhat to do
That file is too large to be an export.Files over 5 MB are refused. Export a shorter date range, or ask the utility's site for CSV rather than PDF.
A file holding both electric and gas is turned awayExport each fuel separately. Most sites have a fuel choice on the download page.
An unknown unit was refusedGreen Button files say their unit in a code; one the app does not know is refused rather than guessed. Try the CSV export instead, which asks you for the unit.
Which column is which?Not an error: the file could be read but the app cannot tell what the columns are. Answer the form; nothing is filed until you do. {{ doc("upload", "Upload", "columns") }}
That statement history was already on file.Nothing new in it. Fine to drop a fresh export over an old one any time.
The file was read but the dashboard looks wrongOpen Raw data and look at the rows under each account. A bill history that lists payments as well as bills is handled, but an unusual layout may have been read as the wrong kind; the column form lets you say so, and you can reach it by dropping the file again.

A scan read the wrong numbers

A photo is read by a text reader, and a dim or skewed photo reads badly. The line above the form says what was found and what was not. Check every figure against the paper before pressing Add bill; fix any that are wrong in the form itself. A straight-on photo in good light, or the PDF the utility sent, reads best.

The comparison with last year says it cannot take the weather out

It needs a ZIP code under About your home, the operator's weather lookups switched on, and usage (not just dollars) for both periods. With fewer than a year of usage it falls back to plain usage and says so.

I can't sign in

  • Too many attempts: eight wrong passwords in fifteen minutes locks the address for a quarter of an hour. Wait, then try again.
  • Forgotten password: there is no reset yet. The operator can delete the account so you can sign up again. Your bills go with it, so if you have access from another browser, export them from Raw data first.
  • Signed up with Google, now asked for a password: press Continue with Google again. An account made through Google has no password.
